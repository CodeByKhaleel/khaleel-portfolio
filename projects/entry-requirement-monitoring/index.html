Monitoring across levels

Requirements span university, nationality, and course levels, with updates gathered from related university emails.

Some entry requirements apply across a university. Others vary by nationality or by course. A monitoring workflow needs to find the relevant update and compare it with the current database record before an update is prepared.

Jira tickets are the checkpoint for updates. A scheduled bot checks tickets, follows the ticket to the related university email, and compares the email content with existing data. When requirements change, the workflow prepares an import file; matching records let the ticket close and the scheduled process continue.

My contribution was keeping the workflow dependable

A colleague led the primary implementation. I supported the system through codebase and script maintenance, quality checks, storage improvements, README documentation, updates from generated files, and Hermes-based checkpoint bots and schedules.
